# PulseCare HMS — Requirements & Risk Traceability Matrix

This document provides end-to-end traceability between coursework risk register items, defect fixes, core requirements, architectural design decisions, and concrete code implementations and automated tests.

> **Note on Concurrency Architecture**: In earlier course tutorials, database concurrency and slot locks were discussed in the context of PostgreSQL row-level locks (`SELECT ... FOR UPDATE`). In PulseCare HMS (built on MongoDB/Mongoose), double-booking prevention is enforced via an atomic database-level **partial unique compound index** on `{ doctor: 1, date: 1, timeSlot: 1 }` with `{ partialFilterExpression: { status: { $nin: ['cancelled', 'noShow'] } } }` alongside MongoDB multi-document transactions where replica sets exist and an atomic fallback query.
